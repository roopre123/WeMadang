# 게임 화면 (공통 틀) (스프린트 3)

- 파일: `src/views/GamePlayView.vue`
- 게임별 빈 화면: `src/components/games/BalanceDebateScreen.vue`, `src/components/games/InterviewScreen.vue`
- 와이어프레임: `../wireframes/game-play.png`, `../wireframes/broadcast-panel-wide.png` 위 ① (넓게 보기)
- 종류: 조작 화면 (일반 웹 화면, 방송에 송출하지 않음). 로그인 후에만 들어옴 (주소 `/games/:id`)
- 헤더, 푸터: `common-frame.md` 공통 프레임 사용
- 방송 패널: `broadcast-panel.md` (**접기 없음**, 항상 펼침)
- 이 화면에 있을 때 표출 화면(OBS)에는 `overlay-game-ready.md` 화면이 나감 (실제 자동 전환은 "송출 상태 자동 전환" 카드)
- **크기·간격은 와이어프레임 픽셀이 아니라 이 문서와 design-rules.md 기준.** 와이어프레임은 구성만 본다

## 목적
게임 목록에서 고른 게임에 들어와 진행하는 화면의 공통 틀. 모든 게임이 같은 틀을 쓰고, 가운데 "게임별 화면"만 게임마다 바뀜

## 배치
- 본문 1200을 왼쪽 **568** / 간격 **24** / 오른쪽 **608**로 나눔 (게임 목록 패널 펼침과 같음)
- 왼쪽 : 위에서부터
  1. 게임 정보 줄
  2. 게임별 화면 자리 (슬롯)
- 오른쪽 : 방송 패널. 위쪽을 게임 정보 줄 위쪽에 맞춤. 높이는 내용만큼 (늘리지 않음). 스크롤해도 헤더 아래 고정 (sticky, `broadcast-panel.md`)
- 본문 위 여백 48 (게임 목록과 같음), 게임 정보 줄과 슬롯 사이 24
- 화면이 길어지면 브라우저 스크롤 (안에 따로 스크롤 만들지 않음)
- **넓게 보기** (`broadcast-panel.md` "넓게 보기") : 본문 1776을 왼쪽 **856** / 간격 24 / 오른쪽 **896**으로 나눔. 게임 정보 줄과 게임별 화면 자리도 856
- 게임별 화면은 **568과 856 두 폭**에서 모두 보기 좋게 만든다

## 요소

### 게임 정보 줄
- 게임 아이콘 40×40 (design-rules.md "게임 아이콘". 게임 목록 카드와 같은 크기)
- 아이콘 오른쪽에 위아래로
  - 분류 표시 : 게임 목록 카드와 같은 알약 모양 (퀴즈형 / 토론형 / 면담형)
  - 게임 이름 : 제목 (28px / 굵게). 길면 한 줄에서 `...`
- 게임 정보 묶음 오른쪽, 사이 24 : [← 게임 목록으로] 작은 보조 버튼 (아이콘 `arrow-left` 16 + 글자)

### 게임별 화면 자리 (슬롯)
- 폭 568 전체, 높이는 들어오는 화면만큼
- 기본 슬롯. 부모가 게임의 `screen` 값으로 고른 게임별 화면을 넣음
- 비어 있으면 아무것도 그리지 않음

### 게임별 빈 화면 (이번 카드)
- `BalanceDebateScreen.vue`, `InterviewScreen.vue` 두 개. 지금은 같은 모양 (나중에 게임별 카드에서 채움)
- `surface` 배경, 모서리 12, 최소 높이 400, 내용 가운데 정렬
  - "게임을 준비하고 있어요" (본문 16px)
  - "진행 화면은 곧 추가돼요." (14px, `text-sub`)
- props, emit 없음

### 방송 패널
- `BroadcastPanel`을 `collapsible: false`, `open: true`로 씀 ([미리보기 접기] 버튼 숨김). [넓게 보기] 버튼은 있음 (`wide` 넘김)
- 미리보기 칸(슬롯) : `OverlayGameReady`를 `OverlayPreviewBox`로 0.3배 줄여 넣음 (게임 아이콘, 이름이 이 화면의 게임과 같음)
- 연결 상태는 **상태에 따라 하나만** 보임 (와이어프레임은 두 상태를 같이 그림)
- 안내 문구는 `broadcast-panel.md` 그대로 (아래 "정할 것" 참고)

## 상태
- 게임 정보를 받은 뒤 : 위 배치 그대로
- 불러오는 중 (`game`이 null) : 같은 틀. 게임 정보 줄 자리에 회색 상자 (아이콘 자리 40×40, 이름 자리 200×28, `surface` 색), 슬롯은 비움. 받은 뒤 틀이 움직이지 않게
- 없는 게임, 불러오기 실패 : 이 화면 대신 `error.md` 화면을 보여줌 (부모가 처리)

## 동작 (emit)
| 동작 | emit |
|---|---|
| [← 게임 목록으로] 클릭 | `back` |
| 방송 패널 [복사] | `copy-url` |
| 방송 패널 [넓게 보기] / [기본 크기] | `toggle-wide` |

- 방송 패널의 동작은 `broadcast-panel.md`

## props
| 이름 | 타입 | 설명 |
|---|---|---|
| game | Game \| null | 게임 정보. null이면 불러오는 중 모양 |
| overlayUrl | string | 표출 URL (방송 패널로 넘김) |
| connected | boolean | OBS 연결 여부 (방송 패널로 넘김) |
| wide | boolean | 넓게 선택 여부 (방송 패널로 넘기고 배치에도 씀. 화면 조건은 CSS가 판단) |

- 기본 슬롯 : 게임별 화면
- 슬롯 `preview` : 방송 패널 미리보기 칸에 넣을 송출 화면

Game : `{ id, name, description, category, screen, icon, color }` (`game-select.md`와 같음)

## 문구
- 버튼 : 게임 목록으로
- 게임별 빈 화면 : 게임을 준비하고 있어요 / 진행 화면은 곧 추가돼요.

## 나중에
- 게임 진행 중에는 [← 게임 목록으로] 대신 [종료] (기획 "2. 기본 방향" : 진행 중에는 페이지 이동 무시, [종료]를 눌러야 게임 목록 송출 화면으로)

## 정할 것
- 방송 패널 안내 문구 : 지금은 "로그인할 때마다 주소가 바뀌어요. 방송 전에 OBS 브라우저 소스에 넣어주세요." (11-21 결정, 표출 URL 로그인마다 새로 발급). 와이어프레임의 "OBS 브라우저 소스에 한 번만 넣으면 돼요."로 바꾸려면 표출 URL 고정 + 스트리머 키 DB 저장이 필요 ("[설계] 딜레이 값 저장 방식"과 같이 정함)
- 게임 안에서 게임을 시작하는 버튼 이름 (게임 목록 카드의 [시작하기]와 겹치지 않게. 의견 : [게임 시작])

## 깨지기 쉬운 경우
- 긴 게임 이름
- 아이콘이 없거나 이름이 틀린 게임 (분류 기본 아이콘 + gray)
- 화면 높이가 낮을 때 (방송 패널 sticky)
- 좁은 너비 (768 ~ 1279) : 방송 패널이 위로 쌓임 (`broadcast-panel.md`)
- 라이트 / 다크 모드
- 넓게 보기 (게임별 화면이 856에서도 어색하지 않은지)
