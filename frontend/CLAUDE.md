# WeMadang 프론트엔드 작업 규칙

이 폴더는 WeMadang(위마당)의 Vue 프론트엔드다.
화면 퍼블리싱(마크업, 스타일)만 Claude가 맡고, 동작(API, 웹소켓, 상태 관리)은 개발자가 직접 붙인다.

## 기준 자료
- 디자인 규칙: `../docs/design/design-rules.md`
- 화면 설명: `../docs/design/screens/*.md`
- 와이어프레임: `../docs/design/wireframes/*`
- 화면을 만들 때는 위 세 가지를 모두 읽고 따른다. 자료에 없는 요소나 문구는 임의로 추가하지 말고 먼저 물어본다.

## 퍼블리싱 규칙
- Vue 3 SFC, `<script setup>` 사용
- 화면과 스타일만 만든다. API 호출, 웹소켓(STOMP), 전역 상태 관리는 만들지 않는다
- 데이터는 `props`로 받고, 버튼 등 사용자 동작은 `emit`으로만 알린다
- props와 emit 목록은 파일 상단 주석에 정리한다
- 화면 확인용 외에는 HTML 태그에 `style="..."` 인라인 스타일을 쓰지 않는다. 스타일은 전부 CSS 파일의 클래스로 적용한다
- 공통 스타일은 `src/styles/` 아래 CSS 파일에 클래스로 만들고, `src/main.js`에서 한 번 불러와서 모든 화면에서 클래스 이름으로 사용한다
  - `variables.css` : `design-rules.md`의 색, 글꼴, 간격, 둥글기를 CSS 변수로 정의 (라이트/다크 두 벌)
  - `base.css` : 기본 글꼴, 배경, 초기화
  - `components.css` : 버튼, 카드, 입력란, 팀 색(파랑/빨강) 등 여러 화면에서 반복되는 클래스 (예: `.btn`, `.btn-primary`, `.card`, `.team-blue`, `.team-red`)
  - `layout.css` : 화면 배치용 클래스 (예: 상단 바, 가운데 정렬, 하단 표기)
- 새 화면을 만들 때는 먼저 기존 클래스를 재사용하고, 두 화면 이상에서 쓰일 스타일은 새 공통 클래스로 `components.css`나 `layout.css`에 추가한다
- 그 화면에서만 쓰는 스타일만 컴포넌트의 `<style scoped>`에 둔다
- 클래스 값에 색 코드나 크기를 직접 쓰지 말고 `variables.css`의 변수를 사용한다
- 클래스 이름은 역할이 드러나게 짓는다 (예: `.delay-input`, `.game-card`)
- 화면 확인용으로 가짜 데이터를 넣은 미리보기 페이지를 만든다 (`src/preview/`)
- 화면 설명에 있는 상태(예: 대기 / 진행 중)는 props로 전환할 수 있게 만든다
- 화면 설명의 "깨지기 쉬운 경우"를 미리보기에 포함한다

## 화면 크기 (조작 화면, 반응형)
- 와이어프레임은 데스크톱(1920 기준) 한 장만 있다. 좁은 화면은 아래 기본 규칙으로 반응형을 만든다
- 1280 이상: 와이어프레임 그대로
- 768 ~ 1279:
  - 좌우 2단 배치는 위아래 1단으로 쌓는다 (왼쪽에 있던 것이 위로)
  - 가로로 여러 개 놓인 카드는 한 줄에 1개
  - 버튼, 글자 크기는 그대로 둔다
  - 헤더는 한 줄을 유지하고, 공간이 모자라면 메뉴 글씨와 간격만 줄인다
  - 모달은 화면 너비의 90%까지
- 768 미만: 768 배치를 그대로 유지한다 (모바일 대응 안 함)
- 미디어 쿼리 기준 너비(1280, 768)는 `layout.css` 한 곳에 모아 두고 모든 화면에서 같은 값을 쓴다
- 위 규칙으로 배치가 정해지지 않는 화면만 먼저 물어본다

## 화면 종류
- 조작 화면: 스트리머가 브라우저에서 보고 버튼을 누르는 화면. 방송에 나가지 않음. 공통 프레임(헤더, 푸터) 사용
- 표출 화면: OBS 브라우저 소스로 방송에 나가는 화면. 1920×1080 고정, 버튼·마우스 올림 효과 없음, 헤더·푸터 없음, 반응형 없음
- 같은 게임의 조작 화면과 표출 화면에 같이 나오는 부분(투표 그래프, 말풍선, 타이머 등)은 `src/components/`에 조각으로 만들어 둘 다에서 쓴다
- 화면 설명 파일에 어느 종류인지 적혀 있다. 없으면 먼저 물어본다

## 파일 위치
- 조작 화면: `src/views/화면명View.vue`
- 표출 화면: `src/views/overlay/화면명OverlayView.vue`
- 재사용 조각: `src/components/`
- 미리보기: `src/preview/화면명Preview.vue`

## Git
- 작업 시작 전에 `git status`를 확인하고, 커밋 안 된 변경이 있으면 먼저 알려준다
- 화면 하나를 끝낼 때마다 작업 내용을 요약해서 커밋 메시지를 제안한다 (커밋은 개발자가 직접 한다)
- `git reset`, `git checkout --`, `git restore`, `git clean`, 강제 push 같은 되돌리기·삭제 명령은 실행하지 않는다

## 금지
- 새 라이브러리 설치 전에 먼저 물어본다
- `.env`, 키, 토큰이 들어간 파일은 읽지도 수정하지도 않는다
- `backend/` 폴더는 수정하지 않는다
